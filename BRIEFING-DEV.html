Lógica da paleta
--caramel (#B8784A) é o accent de ação (botões, CTAs, hover de borda, links ativos). --gold / --gold-light são usados para textos sobre fundos escuros — nunca branco puro. --olive é o accent contextual (badges, categorias, elementos secundários). --dark (#16100C) é o fundo do hero e do featured card. Nunca usar azul, cinza frio ou preto puro (#000) — tudo com temperatura quente. A borda padrão é rgba(94, 69, 53, 0.13).

Notas de Implementação — Página 1 (Link na Bio)
  • Hero background: usar a foto como background-image na seção, NÃO como tag <img>. CSS: background-size: cover; background-position: center 15%;
  • Overlay: pseudo-elemento ::after ou div filho com position absolute, inset 0, gradient escuro (valores acima). z-index do conteúdo acima do overlay.
  • Logo no hero: NÃO usar logo com fundo branco sobre fundo escuro — mix-blend-mode não resolve. Usar logo com fundo transparente (PNG transparente ou SVG). Logo para hero: PENDENTE — solicitar PNG transparente ao cliente. Logo olive (fundo claro): logo-olive.png já recebida.
  • Logo na seção de links: logo-olive.png funciona bem sobre fundo creme #F7F1E8.
  • Seta de scroll: animação bounce com @keyframes: translateY(0) → translateY(6px) → translateY(0), loop infinito 1.2s ease-in-out. Linkando para id="links".
  • Grain texture: usar SVG filter feTurbulence aplicado como pseudo-elemento, opacity 0.04, não afeta performance.
  • Animações de entrada: fadeUp — opacity 0 → 1 + translateY(16px → 0) — 400ms ease-out. Delay escalonado: nome (0ms), cargo (80ms), seta (160ms). Na seção links: cada card com delay 40ms escalonado.
  • Breakpoints: página é mobile-only (max-width 420px). Em telas maiores: centralizar com margin auto, fundo do body = #F7F1E8.
  • Testar em 375px (iPhone SE) e 390px (iPhone 14). Sem scroll horizontal em nenhum breakpoint.
  • Todos os cards: cursor: pointer; transition: all 0.2s ease-out;

Temperatura de cores Sempre quente
Por que nunca usar emojis como ícones
  • Emojis têm renderização inconsistente entre sistemas operacionais (Apple, Android, Windows têm designs diferentes).
  • Emojis não seguem o weight visual do design — parecem colados, fora de contexto.
  • Em um projeto premium, emojis comunicam amadorismo imediatamente — mata a percepção de valor antes do usuário ler uma linha.
  • SVG Lucide: stroke 1.5px, tamanho 14–16px, dentro de container 36×36px com fundo sutil (rgba do bg-alt). Cor segue a paleta.
Por que logo com fundo branco não funciona em hero escuro
  • PNG com fundo branco sobre fundo escuro cria um retângulo branco visível — impossível de esconder sem perda de qualidade.
  • mix-blend-mode: multiply esconde o branco mas altera as cores da logo (as partes escuras ficam transparentes também), resultado imprevisível.
  • A solução correta é sempre pedir ao cliente o arquivo com fundo transparente — PNG transparente ou SVG.
  • Na seção de links (fundo creme), qualquer versão da logo funciona — o problema só existe em fundos escuros.
  • Arquivo pendente da Hadassah: solicitar logo PNG com fundo transparente antes de implementar o hero.
Regra da fonte especial — Impacto pela escassez
  • Livre Baskerville (ou Playfair nas demais páginas) deve aparecer UMA ÚNICA VEZ por página — no elemento mais importante.
  • Na Página 1 (Link na Bio): apenas no nome "Hadassah Perez" no hero. Cargo, links, footer: tudo DM Sans.
  • Quando a fonte especial aparece em mais de um lugar, ela perde impacto — o olho não sabe onde focar e tudo vira "decoração".
  • DM Sans é limpa, moderna e legível — perfeita para interface. Não precisa de "ajuda" da fonte especial para funcionar.

Animação & Scroll

Scroll com efeitos — obrigatório em toda página entregue pela Aigency

Regra inegociável de qualidade
  • Toda página entregue pela Aigency DEVE ter scroll diferenciado. Página sem efeito de scroll = página sem alma.
  • Três técnicas obrigatórias: Parallax no hero, Reveal por IntersectionObserver, Stagger progressivo nos elementos em sequência.
  • Nunca usar animation CSS fixa para elementos abaixo do fold — usar IntersectionObserver para ativar apenas quando visível.
  • Respeitar prefers-reduced-motion em implementações futuras.
A — Parallax no hero
A foto de fundo do hero se move a ~38% da velocidade do scroll, criando profundidade. Implementar via JavaScript com window.addEventListener('scroll') e transform: translateY(). Usar { passive: true } para não bloquear o thread principal.
B — Reveal ao entrar na viewport
Elementos entram com fade-in + translateY(28px → 0) ao ficarem visíveis. Usa IntersectionObserver com threshold 0.12. Três classes disponíveis: .reveal (padrão), .reveal-scale (cards), .reveal-line (ornamentos/linhas). Após animar, o observer para de observar o elemento.
C — Stagger progressivo
Elementos em sequência entram em cascata via CSS custom property --delay. Cada elemento recebe um delay crescente (0ms → 500ms). O efeito cria ritmo visual e guia o olho do usuário pelo conteúdo sem necessidade de JavaScript extra além do IntersectionObserver.

Código de referência — B. JavaScript IntersectionObserver

const observer = new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    if (entry.isIntersecting) {
      entry.target.classList.add('visible');
      observer.unobserve(entry.target);
    }
  });
}, { threshold: 0.12 });

document.querySelectorAll('.reveal, .reveal-scale, .reveal-line')
  .forEach(el => observer.observe(el));
Anti-padrões — Nunca fazer
  • Scroll plano sem efeitos — entrega sem alma, abaixo do padrão Aigency.
  • Usar animation CSS fixa em elementos abaixo do fold — o usuário não vê a animação porque ela já terminou antes de chegar lá.
  • Aplicar .reveal no hero ou em elementos acima do fold — esses elementos já estão visíveis no load, o IntersectionObserver dispara imediatamente e o efeito some antes do usuário perceber.
  • Stagger acima de 600ms — o usuário começa a perceber a espera como lentidão, não como ritmo.
  • Ignorar prefers-reduced-motion — em implementações futuras, envolver os transitions em @media (prefers-reduced-motion: no-preference).
